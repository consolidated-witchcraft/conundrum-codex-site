# Security
## Input Handling & Validation
- All external input MUST be treated as untrusted until proven otherwise.
- Validation MUST occur at system boundaries
- Validation MUST be explicit and deterministic
- DTOs or value objects MUST be used for all inbound data.
- Validation of DTOs and Value Object MUST use Symfony validators
- Invalid input MUST be rejected immediately.

## Output Encoding & XSS Prevention
- Output MUST be escaped by default
- Use framework-native escaping (e.g. Twig autoescape) MUST be used where appropriate.
- Output MUST be encoded based on context (HTML, JS, URL)
- Unescaped data MUST NOT be injected into scripts or markup.

## Authentication & Authorization
- Authentication MUST precede authorization
- Authorization MUST be enforced server-side
- The principle of least privilege MUST be enforced

## Database Security
- Queries MUST be parameterized
- ORM bindings MUST be used.
- String concatenation MUST NOT be used for SQL Queries.
- When not working with complete entities, DTOs MUST be used to avoid exposing irrelevant information.

## Secrets & Configuration
- Secrets MUST NOT exist in code
- Secrets MUST NOT be logged
- Secrets MUST BE injected via environment variable.

## Logging & Error Handling
- Logs MUST NOT leak sensitive data
- Errors exposed to users MUST be safe
- Security-relevant events MUST be logged
- Use structured logging where possible

## CSRF & Request Integrity
- All state-changing operations MUST be protected by CSRF checks.
- GET MUST NOT be used to change state.

## File Upload & Handling
- File input MUST be treated as hostile
- Both MIME type AND extension MUST be validated
- Filesize limits MUST be enforced.

## Dependency & Supply Chain Security
- Dependencies MUST be trusted and maintained

## API & External Communication
- All External systems MUST be treated as untrusted
- All external responses MUST be validated
- Outbound requests MUST be validated (where applicable)

## Rate Limiting & Abuse Protection
- Public interfaces MUST be protected against abuse

## Principle of Least Knowledge
- Systems MUST expose minimal information
- DTOs or transformers MUST be used for output.
- Internal structure MUST NOT be exposed by API structures

## Transport Security
- All sensitive or authenticated traffic MUST be served exclusively over HTTPS.
- HTTP requests MUST be redirected to HTTPS.
- TLS certificates MUST be valid and correctly configured.
- Cookies used for authenticated sessions MUST use the `Secure` attribute.
- Strict-Transport-Security MUST be enabled in production.

## Session Security
- Session identifiers MUST be cryptographically strong and unpredictable.
- Session identifiers MUST NOT be exposed in URLs.
- Session cookies MUST use the `HttpOnly` attribute.
- Session cookies SHOULD use the `SameSite` attribute unless a documented cross-site requirement exists.
- Session identifiers MUST be rotated after authentication and other privilege changes.
- Sessions MUST be invalidated on logout.
- Idle session expiry MUST be enforced.
- Long-lived sessions SHOULD require explicit justification.

## Password Hashing & Credential Storage
- Passwords MUST be hashed using a modern password hashing algorithm supported by the framework, such as Argon2id or bcrypt.
- Passwords MUST NOT be stored in plaintext or reversible encrypted form.
- Passwords MUST NOT be logged, echoed, or included in error messages.
- Password reset tokens MUST be single-use, time-limited, and stored securely.
- Credential comparison MUST use framework or library mechanisms designed for secure verification.
- Hardcoded credentials MUST NOT exist in code, fixtures, or test data intended for shared environments.

## Outbound Requests & Timeouts
- All outbound network requests MUST define explicit timeouts.
- Connection timeouts and total request timeouts MUST both be bounded.
- Outbound requests SHOULD fail fast rather than block indefinitely.
- Retry behaviour MUST be explicit and bounded.
- Retries MUST NOT be used for non-idempotent operations unless explicitly justified.
- External responses MUST be validated before use.
- Outbound requests SHOULD use allowlists or equivalent controls where the destination set is known.
- Server-side requests based on user-supplied URLs MUST be treated as untrusted and reviewed for SSRF risk.

## File Storage Location & Uploaded Files
- Uploaded files MUST NOT be stored in executable paths.
- Uploaded files SHOULD be stored outside the web root where possible.
- Public access to uploaded files MUST be explicit, minimal, and controlled.
- Stored filenames MUST be generated by the system and MUST NOT rely on user-supplied names.
- File metadata derived from user input MUST be treated as untrusted.
- Uploaded content MUST NOT be executed, interpreted, or included as application code.
- Temporary upload files MUST be cleaned up appropriately.

## Enforcement Protocol
When reviewing or generating code, agents MUST:

1. Identify ALL security violations explicitly
2. Classify severity:
   - Critical
   - High
   - Moderate
   - Low
3. Provide a compliant alternative
4. Prefer the most secure viable implementation

### Automatic Refusal Conditions
Agents MUST refuse or flag code that includes:
- Hardcoded secrets
- Raw SQL string concatenation
- Missing authorization checks
- Disabled escaping without justification
- Unsafe deserialization
- Execution of user-provided input

## Symfony-Specific Enforcement

### Mandatory Patterns
- Use Voters for authorization logic
- Use DTOs between controllers and entities
- Do NOT expose Doctrine entities directly in APIs
- Use Symfony Validator for all input

### Security Headers (Required)
- Content-Security-Policy
- X-Frame-Options
- X-Content-Type-Options
- Strict-Transport-Security

### Violations
- Direct entity serialization in responses
- Business logic inside controllers
- Missing CSP or weak policies
